# 手書き構造式エディタ 設計仕様

作成日: 2026-09-05。状態: 計画。アプリ・認識精度・形式互換性は未実装、未実測。

## 1. 確定した要求

| ID | 要求 | 根拠 |
|---|---|---|
| U01 | ブラウザで動く化学構造式エディタ | 初回依頼 |
| U02 | 主な入力はPCのマウス／トラックパッド | 入力環境の回答 |
| U03 | 認識・化学処理・保存・出力をブラウザ内で完結させる | サーバー利用についての回答 |
| U04 | 手書きをリアルタイムに整った構造式へ変換する | 初回依頼 |
| U05 | 変換後に上書き・追記して、構造式を継続編集できる | 初回依頼 |
| U06 | ベンゼン環の頂点にNを書くと、その原子がNになる | 初回依頼 |
| U07 | ざっくりした六角形をベンゼン環にする | 追加依頼 |
| U08 | 二重結合を消して単結合にし、線を足して逆の変更もできる | 追加依頼 |
| U09 | ChemDrawが対応する出力形式をすべて押さえる | 初回依頼。達成には形式別検証が必要 |
| U10 | 実装可能な作業単位・依存関係・合格基準を持つ計画を残す | 最新依頼 |
| U11 | 紙・鉛筆・消しゴムで手作業する感覚を実現する | 計画作成中の追加説明。操作設計の最優先原則 |

以下の仕様はU01–U09を実現するための設計判断であり、ユーザーが個別に指定した数値ではない。

U11を受け、特殊なこすり消しジェスチャーを主要操作とする初期案を修正した。鉛筆で描く／消しゴムで消すという二つの道具を基本にする。結合・元素・環ごとの化学ツール選択は要求しない。描いた形を覚えさせるチュートリアルや、決まった筆順を認識の前提にしない。

## 2. 共通制約

- 実行時の認識・化学処理・保存・出力はブラウザ内だけで完結する。
- 構造式・筆跡・認識結果を外部へ送信しない。クラウド推論へのフォールバックを設けない。
- 初回配信と明示的な更新で静的ファイルを取得できる。取得完了後はネットワーク切断下で再起動・編集・出力できる。
- 必須操作はマウス／トラックパッドのドラッグで成立する。筆圧、ペン種別、WebGPUを必須条件にしない。
- 最初の対応対象はデスクトップ版Chrome・Edge・Safari・Firefoxの実装開始時の安定版。具体的なOS・ブラウザ・CPU・RAMをP01の実行環境記録に固定する。
- 入力待ちや文字認識中もキャンバス描画を止めない。
- 原子ID・結合ID・筆跡との対応を編集の途中で付け替えない。
- 描画だけで無関係な原子の座標・結合・立体化学を変更しない。
- 確定していない認識候補を化学ファイルに含めない。除外対象がある場合は出力対象を明示する。
- 書きかけや化学的な矛盾がある文書もネイティブ形式で保存・復元できる。
- ファイル形式の対応は拡張子やボタンの有無で判定しない。再読込と外部ソフトでの検証記録を必要とする。
- この計画の作成ではアプリのコード作成、依存パッケージの導入、公開、コミットを行わない。

## 3. 代表操作と状態遷移

| 操作ID | 入力 | 結果 | 間違ってはいけないこと |
|---|---|---|---|
| I01 | 空白に閉じた、六つの角を持つ大まかな輪郭 | 六原子・六結合のベンゼン。二重結合は交互に三本 | 単なる丸や五角形を必ずベンゼンにしない |
| I02 | ベンゼンの頂点に複数ストロークのN | 同じ原子IDを保ったピリジン型のNへの置換 | Nの各線を枝として残さない |
| I03 | 消しゴムで二重結合を構成する片方の線をなぞる | 対象の結合次数だけ2→1 | 一方だけを消して環の接続を切らない。芳香族フラグで二重結合が復活しない |
| I04 | I03を三本に対して実行 | 六員飽和炭素環 | 一本消した時点では他の二重結合を消さない |
| I05 | 単結合に沿って別の線を足す | 対象の結合次数1→2。三本を交互に足すと芳香族判定が戻る | 同じ頂点間の独立した結合を重複作成しない |
| I06 | 頂点から線を伸ばす／ジグザグを描く | 接続された置換基／炭素鎖 | 近くを横切るだけの線を勝手に接続しない |
| I07 | 原子ラベルに別の元素記号を上書き | 対象原子の元素を置換 | 下のラベルと新しいラベルを結合した文字にしない |
| I08 | 消しゴムで単結合、または多重結合の全描画線を消す | 対象結合を削除し、環が開く | 一方の線を消しただけでは接続を切らない |
| I09 | 操作直後のUndo／Redo | 筆跡・グラフ・配置・候補が一操作単位で戻る／進む | 一筆ごとの内部処理を大量にUndoさせない |
| I10 | 描画中に画面外へ移動／pointercancel | 未完の筆跡を保持し、確定しない | 閉じた環や削除動作として扱わない |

六角形→ベンゼンはこのアプリ固有の入力規則。新しく描いた環の認識時にだけ使う。読み込んだ六員単結合環や、二重結合を消した既存環を再びベンゼンにしない。

二重結合の片方を消すと、表示しているKekulé構造のその結合だけを単結合にする。内側・外側のどちらでも同じ意味とする。残る一本は同じ原子間を結ぶ位置へ最小限だけ整える。水素数・芳香族性・原子価は化学エンジンで再評価する。無関係な結合次数を芳香族性維持のために変更しない。N→Oなどが化学的に不自然になる場合は自動確定せず、問題の箇所と候補を残す。ユーザーが候補を選んだ場合は矛盾を表示したまま編集を続けられる。

## 4. 画面とマウス操作

初期表示は白い紙面。常時見える道具は鉛筆と消しゴム。上部に文書名、Undo、Redo、開く／保存、出力を置く。出力形式や高度な設定は使用時に開く。原子・結合・環ツールの選択を通常描画の前提にしない。細かいパラメータの調整を描き始める前に求めない。

- 鉛筆でドラッグ: 手書き。マウスとトラックパッドを同じ入力契約で扱う。
- 消しゴムでドラッグ: 円形の消去範囲を表示し、触れた筆跡・描画線・文字を消す。ボタン選択とEを押している間の一時切替の両方を提供する。Eを離すと元の道具に戻る。
- Space＋ドラッグ: 画面移動。スクロール／ピンチ: ビューポートの移動・拡大縮小。
- クリック: 対象選択。選択表示から移動・削除できる補助操作を用意する。
- Ctrl/Cmd＋Z: Undo。一般的なRedoショートカットも対応する。
- Esc: 候補表示を閉じる。原筆跡は保持する。
- 曖昧な候補: 該当箇所の近くに最大三件。「元の手書きのまま」も選べる。
- 出力時に未確定部分があれば、その部分を表示し「確定済み部分を出力」「戻って直す」を提示する。

色だけに頼らず、未確定部分は筆跡、候補は薄い整形図、確定済みは実線で区別する。ラベルや候補はキーボードでも選択可能にする。

### 消しゴムの意味

- 未変換の筆跡: ブラシが通った点列を切り取り、残りの筆跡から再認識する。筆跡全体を一括で消さない。
- 変換済みの結合: 各描画線の消去量を積算する。単に一瞬触れただけではトポロジーを変更しない。初期の確定閾値は各線の長さの60%とし、P07/P10で意図一致率と手数から調整する。
- 二重結合: 一方だけが閾値に達したら2→1。消去操作の開始時に存在した両方の線を消した場合だけ結合を削除する。途中の再描画で同じ操作が新たな単結合を巻き込まないよう、対象を操作開始時の描画モデルに固定する。
- 原子ラベル: Nなどの文字だけを消したら炭素の省略表記に戻し、接続した結合は保持する。文字が消えた事実をユーザーに即座に見せ、必要な原子価検証を行う。複数文字のラベルは文字単位で仮消去し、残ったラベルを再解釈する。
- 線とラベルをまとめて消す: ブラシが実際に覆った要素だけを対象にする。片端が消えた結合の残存原子は保持する。接続を失って可視要素もない省略炭素だけを取り除く。
- 消去も一回のドラッグで一つのUndoにまとめる。消去途中は削れた見た目を出し、pointerupで構造変更を確定する。Escで消去前の状態へ戻せる。

鉛筆での走り書きを削除コマンドとは扱わない。特殊ジェスチャーによる削除は初期仕様に含めない。

## 5. 増分認識

### 5.1 保存する入力

各点の画面座標・文書座標・相対時刻・strokeIdを保存する。筆圧は取得できれば補助情報とする。描画開始時のビューポート変換を固定し、描画中のズームによる座標ずれを避ける。pointer captureを使い、coalesced eventsが無い環境では通常のpointermoveに戻す。

### 5.2 候補生成

1. 重複点と微小な揺れを除く。元データは残す。
2. 鉛筆入力から線分・折れ線・閉曲線・文字を競合候補として作る。消しゴム入力は別の決定的な消去経路へ送る。
3. 近傍原子、結合の描画線、既存ラベル、最近の筆跡との関係から編集操作に変換する。
4. 化学的に成立しない候補は自動確定対象から外す。原子価だけで意図の正解を決めない。
5. 学習用データでなく独立した検証用データで決めた閾値と候補間の差により、自動確定か保留を選ぶ。

初期の幾何閾値は文書上の標準結合長Lに対する比で管理する。端点接続距離0.18L、平行線間隔0.08–0.28L、平行度15°以内、重なり率0.55以上、環閉鎖距離0.25Lを初期値とする。固定画素数で判定せず、P10で実測して変更履歴を記録する。

六角形は始点・方向に依存しない輪郭の単純化と正六角形への当てはめで判定する。1ストロークでも複数ストロークでも受理する。新しく描いた線が環としてまとまった場合、直前の仮線分を同一の環作成トランザクションへまとめる。

文字は回転を完全には正規化しない。NとZ、CとO、ClとC＋結合など、向きや追加筆跡が意味を変える。初期対象はN/O/C/H/S/P/F/Cl/Brと線・環。元素の入力範囲はP12で全元素の候補選択に広げるが、全元素の手書き自動認識を検証前に宣言しない。

### 5.3 確定と追記

状態は `collecting → preview → committed` または `pending`。描画は次フレーム、候補生成は入力中にも間引いて実行し、基本のまとまり判定は最後のpointerupから280msで開始する。280msは保証値でも強制確定時刻でもない。

遅い書き手のNやClについては、直近の局所トランザクションに筆跡を再結合できる。元の対象のrevisionと、後続操作の依存関係が一致する場合のみ、そのトランザクションを置換する。別の操作が対象を変更した場合は自動で過去を書き換えず、新しい候補を提示する。80/300/900/1500msの筆間隔を試験する。

認識要求にrequestId、baseRevision、対象ID集合を付ける。結果到着時に対象が変更されていれば捨てて必要な範囲だけ再認識する。古い結果によるUndoの取り消し、読み込んだ別文書への結果混入を防ぐ。

### 5.4 認識方式の選定

最初は幾何処理と複数ストロークのテンプレート照合を使う。少数の記号を低負荷で評価できるため。手書き化学構造の増分編集をそのまま提供する既成モデルがあるとは仮定しない。

P10の精度・保留率を満たさなければ、P11で小型分類モデルを同じ評価セットで比較する。64×64の筆跡画像と筆順情報を入力候補とし、ONNXでブラウザCPU上に載せる。学習は開発用ローカル環境で行ってよく、製品の実行時サーバー処理とは区別する。提供された筆跡だけを使用し、自動収集・送信をしない。

モデルは記号候補を返し、分子全体やSMILESを直接生成しない。模型が小さくても実測が閾値を満たさなければ採用しない。ユーザーごとの補正例は明示的に候補を選んだ例だけを端末内へ保存し、モデル自身の推定を正解として自己学習させない。

## 6. データと化学処理の境界

正本は分子グラフ・描画配置・筆跡・履歴を持つDocument。SMILESを編集用正本にしない。SMILESには編集ID、紙面配置、筆跡、一般の反応図形を完全には保存できない。

原子・結合は安定IDを持つ。分子レコードは非連結成分を含められる。塩を勝手に複数のSDFレコードへ分割しない。反応の役割、注釈、略記、S-group、配列、3Dシーンは独立した文書要素として追加する。

編集グラフには表示する1/2/3の結合次数を持たせる。芳香族性・原子価・暗黙水素数・CIPはrevision付きの派生情報。編集時に派生情報を破棄して再計算する。立体結合には始点・終点を保持し、内部インデックスの並べ替えだけで立体反転しない。

化学エンジンへの入出力は専用Adapterだけを通す。初期の分子変換はMOL V3000、文書全体の交換はKET/CDXMLの適合試験を経て採用する。インポートで新しいIDを付けることと、既存編集中のID保持を区別する。未知の属性を読み飛ばして「完全に読み込めた」と表示しない。

レイアウトは描画した位置と接続先を固定し、編集領域内の未固定点だけを調整する。全体整形はユーザーが明示的に選んだ場合のみ。複数分子の配置や反応矢印の位置も保持する。

## 7. 技術構成と選定ゲート

| 境界 | 採用案 | 採用条件／代替 |
|---|---|---|
| Webアプリ | TypeScript、React、Vite | P01でlockfileとビルドを固定。APIサーバーなし |
| 筆跡 | Canvas 2D、Pointer Events | coalesced events無しでも成立 |
| 構造式 | SVG＋グラフ由来の描画モデル | 各線がbondId・内側線か外周線かを持つ |
| 幾何・文字認識 | TypeScriptの幾何処理とテンプレート照合 | P10不合格時にP11のONNX分類器を比較 |
| 化学処理 | IndigoのWASMを専用Workerで使用 | P03で直接呼出し・バイナリ形式・メモリ解放を検証 |
| 代替接続 | ketcher-standaloneの構造サービス | 直接WASMの包装が不安定なら限定利用。編集UIを依存先にしない |
| モデル実行 | ONNX Runtime Web、WASMを基準 | WebGPUは任意の高速化。自動ダウンロードする巨大モデルを前提にしない |
| 保存 | IndexedDB＋ネイティブJSONダウンロード | 破損・容量不足・複数タブ競合をP09で試験 |
| オフライン | 同一オリジンの静的ファイル＋Service Worker | 更新は編集中に強制適用しない |
| 検証 | Vitest、Playwright、ブラウザ実機、ChemDraw実機 | 自動試験だけで実機互換を完了扱いにしない |

Ketcher公式のstandalone実装は認識メソッドを未対応としている。Ketcherを導入すれば手書き認識も解決する、という計画にしない。[実装](https://raw.githubusercontent.com/epam/ketcher/master/packages/ketcher-standalone/src/infrastructure/services/struct/standaloneStructService.ts)

Indigo WASMの呼出し方は公式のWorker実装を根拠にする。配布パッケージとソースの差異はP03で固定バージョンに対して検証する。[Worker実装](https://raw.githubusercontent.com/epam/ketcher/master/packages/ketcher-standalone/src/infrastructure/services/struct/indigoWorker.ts)

## 8. 出力の範囲

[出力対応計画](../../planning/format-compatibility.md)を正本とする。比較基準は2026年5月のChemDraw公式機能表で確認できる出力項目の和集合。エディションを黙ってPrimeだけに狭めない。ユーザーのChemDrawバージョンが判明した時点で追加差分を登録する。

SMILES/MOL/SDF等の分子形式、CDX/CDXML等の文書形式、画像、反応式、配列、旧形式、3MFを個別に管理する。CIFは基準資料では読込項目なので、その事実を記録し、出力必須と混同しない。OLEはOS連携であり、ブラウザだけという要件との衝突を残す。拡張子を持つファイルのダウンロードをOLE互換と呼ばない。

ChemDraw実機と旧形式の資料が必要な箇所は外部依存として記録する。それらが得られない場合も主要形式の実装は進められるが、全形式・完全互換の完了条件は満たさない。

## 9. リリースと受入

- M0: 化学エンジンのブラウザ実行、筆跡記録、出力方式の成立性を確認する。
- M1: 六角形→ベンゼン→N→結合の増減→Undo→SMILES出力が、実際のマウス操作で一巡する。
- M2: 手書きの個人差・遅い追記・オフライン復元に耐える。
- M3: 通常の有機分子を編集し、主要分子形式・ChemDraw形式・画像で交換できる。
- M4: 反応式・配列・旧形式・3D出力を実装し、形式ごとの外部検証を完了する。
- M5: [評価仕様](../../planning/recognition-evaluation.md)の速度、精度、操作回数、情報保持の条件を満たす。

M1を製品全体の完成と呼ばない。M4の未達項目をM3の成果に隠さない。各マイルストーンは動くデモ、再現可能な試験結果、残存する制約の三点で判断する。
